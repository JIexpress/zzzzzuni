## 任务简报（主控写）

### 0. 现状（先读再动手）

- `UnityProject/Assets/ZFrame/Data/Config/`：ConfigRow.cs / ConfigTable.cs / ConfigService.cs / EnemyConfigRow.cs（**手写行类型**）/ EnemyConfigTable.cs
- Editor 侧：`UnityProject/Assets/ZFrame/Data/Editor/ConfigValidator.cs`、`ConfigAssetSetup.cs`（另有 CsvImporter/CsvExporter 能力散布其中，施工前先盘点真实落点）
- 测试：EditMode 里 Config 相关既有用例全绿是基线

### 1. 做什么

1. **代码生成器（Editor asmdef）**：输入=一张配置表的 schema（推荐从 CSV 表头行推导：列名+类型标注，或已有 SO 字段反射），输出=C# 行类型源文件（属性/字段 + 类型映射 string/int/float/bool 至少四类）
   - 生成触发：菜单项（Tools/…）+ 导入管线钩子（CSV 变更重导入时重生成）二选一或都做
   - 生成产物放约定目录（如 `ZFrame/Data/Config/Generated/`），文件头带 `// <auto-generated>` 标记与源表路径
2. **把 EnemyConfigRow 迁移为生成产物**（首个真实消费者）——生成结果与手写版字段语义一致；`EnemyConfigTable`/`ConfigService` 引用不破坏
3. **校验联动**：生成时把 ConfigValidator 的列校验规则（类型/必填/范围）带上——表头非法时报错而不是生成坏代码
4. **不破坏既有能力**：CSV↔SO 双向导入导出、自定义 inspector、既有 EditMode 用例全绿

### 2. 测试与验证

1. EditMode 新增：样例 CSV → 生成代码 → 编译通过 → 行解析往返（CSV→行对象→字段值断言）
2. 坏表头（类型拼错/列名重复）→ 生成器报错且不产出坏文件
3. 全量 EditMode 相关段跑绿；架构校验器 26 asmdef / 0 违规不破

### 3. 铁律

- 生成器代码与生成产物都入库（产物是源码）；UTF-8 无 BOM / LF
- 不引第三方代码生成依赖（用字符串模板//roslyn 均可，倾向简单可控）
- 施工不 commit、不改看板/HANDOFF
- 本任务不动 ZRender/Native 任何文件

### 4. 完成判据

- 「加一张新配置表 = 放 CSV → 重导入 → 行类型自动出现 → 直接用」，全程零手写行类型
- EnemyConfigRow 成为生成产物（或并存迁移说明+演示表），既有用例全绿
- 08 对照 #11 从「半」改判「已实现」的证据链在施工报告里
