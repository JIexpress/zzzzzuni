## 三、探针：不伪造"已验证"

**背景**：引擎里出现过"注释写着做了真实设备探测、代码实际传的是空设备"的情况，结果是能力被标成不支持，而硬件其实支持。这一类错误比缺功能更贵——它让人以为已经测过了。

### 探针合格的判据（四条全中才算）

1. **真跑**：有可执行入口，能当场跑出结果，不是一段注释
2. **有真实输入**：读的是设备/磁盘/文件/API 的真值，不是常量
3. **缺就是缺**：拿不到数据时输出 `MISSING` + 原因，**不填 0、不填默认值、不写"通过"**
4. **可复核**：输出能被第三个人重跑一遍对得上

### 不合格的写法（见到就重写）

| 写法 | 为什么不合格 |
|---|---|
| `return true;` 加一句"硬件支持" | 常量冒充探测 |
| 传空设备/空参数去问能力 | 问出来的答案不是这台机器的 |
| 注释声称"已实测"，但没留结果 | 无法复核 |
| 把"没测"写成"暂无问题" | 缺数据被抹成通过 |

### 探针放哪

- 一律放 `探针/`，文件名单列，`探针/README.md` 里登记"测什么/怎么跑/最近一次结果"
- 探针**不接入**引擎任何流程，不改引擎行为；它只负责回答"到底是什么"
- 探针自己产出物写 `探针/out/`，带时间戳
