## 3. 已知环境坑（每一条都真实踩过，会浪费你半天）

### 3.1 PowerShell 脚本必须 UTF-8 **带 BOM**
PS 5.1 读无 BOM 的 UTF-8 会按 GBK 解析，**中文注释里的字符会让解析器报"意外的标记 }"这类假语法错**。
新建/修改 `.ps1` 后自查：
```powershell
$b=[IO.File]::ReadAllBytes($p)[0..2]; "{0:X2} {1:X2} {2:X2}" -f $b[0],$b[1],$b[2]   # 应为 EF BB BF
```

### 3.2 代理变量大小写重复会让 Unity 启动失败
`http_proxy` 与 `HTTP_PROXY` 同时存在时，`Start-Process` 报
`Duplicate case-variant variables present` → 六段里的 Unity 段直接 FAIL。
跑测试前（同一进程内）：
```powershell
foreach ($n in @('http_proxy','HTTP_PROXY','https_proxy','HTTPS_PROXY','all_proxy','ALL_PROXY','no_proxy','NO_PROXY')) { [Environment]::SetEnvironmentVariable($n,$null,'Process') }
```
Bash 侧：`unset http_proxy https_proxy all_proxy`。

### 3.3 Unity 批处理必须走 **Git Bash**，且测试不能带 `-quit`
- Bash 侧禁止转调 `powershell`（会被安全策略拒），六段用 **PowerShell 工具**
- EditMode/PlayMode 跑测试**不要加 `-quit`**；跑前 `tasklist | grep Unity.exe` + 删 `UnityProject/Temp/UnityLockfile`
- xml 出现但 5 分钟不退 → `taskkill //PID <pid> //F`
- **证据以 results.xml 为准**，不看日志猜
- **Unity 必须经 Git Bash 启动**：用 shell 宿主直启会出现 licensing "假退出"（进程正常退出但没干活）

### 3.4 帧率/耗时证据只在空载时可信
`CompatTelRunner`（兼容性遥测）与 `MsMpEng`（Defender）能吃掉 20–40% CPU，实测把 430fps 压到 310fps，
并制造出"关态比原管线快 14%"的荒谬值。
**做法**：跑性能类验证前先跑 `Tools/check_machine_quiet.ps1`；跨跑比较不可信时，改用**同一次运行内切换 A/B** 的强制对照。

### 3.5 证据别写 `%TEMP%`
`zfg` 代理的日志默认写 `%TEMP%\zfg_probe.log`，曾因此整轮证据丢失。
**一律用 `ZFG_HOOK_LOG` 指到 `TempLogs/<任务>/`**。

### 3.6 ctest 在六段里可能被判 `binary not usable here` 而跳过
脚本的探测问题（已记录，未修）。手动补：
```bash
ctest --test-dir Native/build -C Release
```

### 3.7 构建产物噪音
`UnityProject/Assets/Plugins/ZRender/zrender.dll` 是受跟踪的构建产物，每次构建必变 `M`（PE 时间戳）。
**提交前 `git checkout --` 丢弃**，别带进 commit。Editor 跑完可能改写 `URP_*.asset`（`m_Prefilter*` 关键词），同样 `git checkout` 还原。

### 3.8 签名与密钥保管（release keystore，TASK-A-AND-08）

Android 正式包用**本地自签 release 证书**（`CN=ZFrame`），不是 Unity 自动生成的 `CN=Android Debug`。

| 项 | 值 |
|---|---|
| keystore | `C:/Users/1/Android/keys/zframe-release.keystore`（**仓库外**，JKS，RSA 2048，有效期 10000 天 ≈ 2054-03-21） |
| 口令文件 | `C:/Users/1/Android/keys/keystore.properties`（`storePassword` / `keyAlias` / `keyPassword`，**仓库外**） |
| alias | `zframe` |
| 证书 SHA-256 | `54:13:B0:48:55:DB:61:3B:66:0E:83:B4:39:E3:E9:02:58:DC:D9:F7:6D:72:B6:46:2B:DC:3E:0D:4A:02:2C:B0`（指纹不是秘密，可公开核对） |

读取方式（`UnityProject/Assets/Game/Editor/PlayerBuild.cs` → `ConfigureAndroidSigning`）：

- 口令与路径**环境变量优先**，仓外 properties 文件兜底：
  `ZFRAME_KEYSTORE_PATH` / `ZFRAME_KEYSTORE_PASSWORD` / `ZFRAME_KEY_ALIAS` / `ZFRAME_KEY_ALIAS_PASSWORD`。
- 两处都取不到（或 keystore 不存在、或 keystore 落在仓库内）→ **报错中止构建**（exit 1）。
  **绝不静默退回 debug 签名**：debug 包在本机能装，换台机器装不上，且商店不可用——
  "以为是正式包其实是 debug"是这条管线最贵的错误。
- 口令只进 `PlayerSettings.Android.*Pass` 的内存字段，**不写日志**（日志只打来源与 `<redacted>`）。

**备份要求（必须做，别只留在这一台机器上）**：

1. `zframe-release.keystore` 与 `keystore.properties` **一起**备份到两台以上的离线介质 / 密码管理器，
   并把口令单独记进密码管理器（别和 keystore 放同一处）。
2. 备份要能通过 `keytool -list -keystore <file>` 打开核对（只读校验，不打印口令）。

**丢失后果（最坏情况，务必记住）**：

- **同一个包名（`com.ZFrame...`，以 ProjectSettings 的 packageName 为准）将永久无法更新**——
  Android 只接受签名相同的升级包，旧签名一旦丢失，任何新包都会被拒（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。
- **唯一出路是换包名重新上架**：老用户不会自动迁移（存档在 `LocalLow`/应用私有目录，跨包名搬不过去），
  商店的下载量/评论/内购关系一并清零。
- 因此：**keystore 与口令的备份优先级等同于源码本身**，且证书有效期到 2054 年之前都不用轮换
  （换证书同样等于换包名，除非用 Play App Signing 这类托管方案——本项目已决定不用）。

## 4. 工作方式约定（项目的治理规则，别破坏）

- **三角色**：主控（写简报/收口/提交）、施工代理、验收代理。**施工与验收必须是不同实例**，验收只认自己跑出来的数字。
- **一任务一 commit**；施工代理**禁止** `git commit`/`git add`，提交由主控做。
- **每个任务一份日志** `Docs/Logs/TASK-<ID>.md`，四节：简报（主控）/ 施工报告 / 验收清单（主控）/ 验收结论（验收代理）。
- **任务闭环必须同时改三处**：日志状态行、`TASKS.md` 看板行（**改原行，不追加**）、`WORKLOG.md` 一行。
- **验收标准不能放水**：允许 `PASS with 受限`（如实披露的未达项），不允许把"没做"写成"做了"。
- **子代理额度**：主对话档的 429 可以用 `model: "lite"` 绕开（本项目全程用 lite 档跑施工/验收，够用）。
