## 5. Track B —— ZRender 渲染内核（核心新增）

### 5.0 双管线并存与迁移策略（B0，风险隔离）

- ZRender 以**独立自研 SRP**形式实现（RenderPipelineAsset→ZRenderPipeline: Cull→收集→移交原生），不 fork URP；
- **URP 档位保留**：画质档位表同时挂 URP 与 ZRender 的 PipelineAsset，编辑期一键切换对比，ZRender 达到"同等场景下视觉对等 + 帧耗不劣于 URP"（对等闸门）后才设为默认；
- Unity 侧仅承担：场景/物体宿主、剔除 API（CullingResults）、纹理/网格资产容器、SRP 调用时机。**真正的渲染调度全部在原生层**；
- 网格/材质数据流：不走 Unity 运行时逐 Renderer 提交，而是**离线烘焙进自管 SoA 缓冲**（§5.4 资产烘焙管线），原生层直接消费——同时服务数据内核与 bindless 批处理。

### 5.1 DataKernel 数据内核（B1，R1）

- **不用通用 ECS**（不引 DOTS/ECS 包），自写最小数据内核，仅服务渲染与高性能玩法（如大规模实体）：
  - **128 位组件掩码**：archetype 身份 = 4×uint64 位掩码，每组件占 1 位；
  - **约 3 周期定位组件偏移**：`slot = POPCNT(mask & (bit-1))`（低位置位计数），x64 用 BMI2 `TZCNT/POPCNT` 指令（Zen4 原生支持，1~3 周期）；C# 镜像用 `System.Numerics.BitOperations`（JIT 到同指令）；
  - **SoA 连续存储**：chunk = 16KB（L1 友好），chunk 内各组件列式连续数组；跨 chunk 链表 + 位掩码索引；
  - 查询 = 掩码 AND + 比较，命中 archetype 后线性扫描 chunk，缓存命中率对齐 DOTS 水准；
  - API：`world.Spawn(mask)` / `world.Each<T0,T1>(mask, callback)` / 写回脏标记；
- **基准验收**（doctest + benchmark 场景）：掩码定位 ≤ 3 CPU 周期（反汇编确认无软模拟）、百万实体遍历吞吐与 GC 零分配报告存档；
- C++ 实现核心 + C# 绑定（渲染实体、实例数据、可见性结果都住这里）。

### 5.2 手写 Render Graph（B2，R3）

- **声明式两阶段**：Record（各 Feature 声明 Pass 与读写资源句柄）→ Compile（无 Pass 剔除、拓扑排序、资源生命周期推导）→ Execute（原生命令录制）；
- **资源生命周期**：每个临时资源带 first/last use 区间，区间不重叠者**内存别名复用**（transient pool，降显存峰值）；
- **屏障合并与精细化同步（你点名的重点）**：
  - 每资源维护"上一次访问状态"（Vulkan 语义：layout + accessMask + stages）；
  - Compile 期计算实际状态迁移序列，**只在真实冲突处发屏障**；同性质相邻屏障合并；只读区间共享一个屏障；
  - 支持 **split barrier**（早提交、晚消费，填气泡），对齐主机级实践；
- 调试：RG 可视化（Pass 图/资源区间甘特图/屏障列表，工具层输出）+ RenderDoc 逐 Pass 验证；
- 单测：非法读写未声明资源 = 编译期报错；死 Pass 自动剔除断言；别名复用显存统计断言。

### 5.3 RHI —— Vulkan 语义抽象层（B3，R2）

- 接口语义照 Vulkan 设计：`Device / Queue / CommandList / Swapchain / Image / Buffer / ImageView / DescriptorSet / PipelineLayout / PipelineState / Barrier(ImageMemoryBarrier 语义)`；
- **后端**：
  - **D3D12**（主后端，本机日常开发/验收）：屏障→ResourceState + EnhancedBarriers 映射、描述符堆、root signature；
  - **Vulkan**（第二后端，验证抽象忠实度 + 未来 Android/SteamDeck 路径）：直接 1:1，需本机装 Vulkan SDK；
  - **Metal 3**（预留目录与接口桩，本机无 Apple 硬件，不承诺验收，见 §11）；
- **Bindless 映射（跨后端统一模型）**：全局大描述符表，材质/贴图/顶点缓冲全驻留，draw 仅带 drawID 索引：
  | 后端 | Bindless 落地 |
  |---|---|
  | D3D12 | SRV descriptor heap（GPU 侧索引）+ root constant 传 drawID |
  | Vulkan | `descriptorBindingPartiallyBound + updateAfterBind` 大 set |
  | Metal 3 | Argument Buffers Tier 2（预留） |
- PSO 缓存（磁盘缓存 + 热路径零创建）、GPU 时间戳查询（每 Pass 计时，喂性能 HUD 与 FrameGovernor）；
- 严格分层：zrender 上层永不直接见后端头文件（CMake 目标隔离），抽象泄漏 = 架构校验器报错。

### 5.4 剔除-排序-批处理一体化（B4，R4）

- **共享可见性**：一次剔除（视锥 + 遮挡，遮挡用 Hi-Z 保守判定，可选 GPU 驱动），**主视图/阴影视图/SSR 探针视图共用同一份可见性结果**（按视图掩码过滤），杜绝重复剔除（你点名的目标）；
- **资产烘焙管线**（工具层）：fbx → 顶点/索引重打包进 SoA 大缓冲（按 shader 签名分桶）、材质参数打包成结构化数组、贴图烘焙进 bindless 表；Addressables/编辑器菜单触发增量烘焙；
- **64 位 sort key 单一排序**：
  - 不透明：`[透光标志0][深度前→后24bit][Shader 8][材质实例 16][网格 8][杂项8]`；
  - 半透明：透光标志 1 + 深度后→前；
  - **"按状态聚簇"是排序的天然产物**——排完序相邻即同 PSO/材质，无需额外分组 pass；
- 提交：排序后生成 **indirect draw 包**（同桶合批/实例化），CPU 只上传 drawID→参数小表，配合 bindless 实现"一次根签名，全程不切绑定"；
- 验收：示例场景 DrawCall/SetPass 统计对比 URP 基线，报告落盘。

### 5.5 光照与阴影（B5，R5）

- **实时光源混合（hybrid）**：clustered 前向（体积簇内光源分配）为主，静态光源可选烘焙探针注入；PBR BRDF（GGX）全流程；
- **SSR**：Hi-Z ray march（复用 §5.4 的 Hi-Z），半分辨率 + 时空降噪（与 TAA 共享 jitter 历史），粗糙度衰减到 SSR 消失时回落到 IBL/探针；
- **动态 GI 近似**：探针辐射缓存（DDGI 思路：世界空间探针网格 + 深度屏蔽八面体贴图 + 时空辐照度累积），动态光源与移动物体可弹射，成本可控（探针更新分摊帧）；
- **NPR 风格线**：卡通 ramp / SDF 脸部阴影 / 描边（课程 M27-148 教学内容直接落地），与 PBR 共存：材质系统按 shader 桶分流，互不干扰；
- **全场景动态阴影**：CSM（近距）+ 逐光阴影图（点光立方体/聚光）+**阴影剔除与主视图共享可见性 + 阴影 LOD/距离衰减 + tile 剔除**；PCF 与 EVSM 双路径；阴影 pass 进 RG 统一调度（屏障合并受益方之一）。

### 5.6 超分与 AA —— UpscalerChain（B6，R6）

- **统一接口**（版本无关，喂 jitters/mvec/exposure/反应性掩码，产出到动态分辨率的目标图）：
  ```
  IUpscaler: Capability(设备查询) / OnCreate(desc) / Eval(frameArgs) / OnDestroy
  链接器：运行时按能力矩阵自动选优，设置界面可手动覆盖
  ```
- **后端与选择矩阵**（按你的定位：FSR4.1 主、FSR3.1 给非 AMD 回退）：
  | 硬件 | 首选 | 回退 |
  |---|---|---|
  | AMD RDNA 3/4（含本机 780M） | **FSR 4.1（ML）** | FSR 3.1 |
  | AMD RDNA ≤ 2 | FSR 3.1 | TAA+DRS |
  | NVIDIA（RTX 50+） | DLSS 5（Streamline） | FSR 3.1 |
  | NVIDIA（旧卡）/ Intel / 其他 | FSR 3.1 | TAA+DRS |
  | Intel Arc（可选，低优先） | XeSS（SDK 直连） | FSR 3.1 |
- **FSR 路径（首期必做）**：直接链 AMD FSR SDK（C API，D3D12/Vulkan 句柄我们 RHI 自持，绕开一切 Unity 管线限制）；FSR 4.1 与 3.1 同 SDK 双实现，运行时按 `设备代际` 探测切换；FSR Frame Generation 列为后续可选项（不进首期验收）；
- **DLSS 5 路径（首期建骨架）**：NVIDIA Streamline 封装成 IUpscaler 后端；本机无 NVIDIA 卡，验收 = 编译/链接/能力门控逻辑单测 + 真机验证列为"受限项"（外部硬件/远程会话补验，§11）；
- **XeSS（可选）**：官方 Unity 插件已停更 → 若做则 SDK 直连；不承诺排期；
- 自研 TAA + 动态分辨率兜底（所有硬件可用的最终回退，也服务低配档）。

## 7. 工程治理（★强制落实，所有角色必须遵守）

### 7.1 原则

1. **一切状态落盘**：会话/上下文随时可能断（网络波动、限额、频控、人为关闭），**磁盘文档是唯一权威**，对话记忆只作辅助；
2. **主控不写业务代码**：主控只做方案、拆任务、派发、验收裁决、提交；代码全部由施工子代理产出；
3. **任何 AI agent 或人**读完 `AGENTS.md → HANDOFF.md → TASKS.md` 三个文件即可接管主控，不依赖任何特定平台/工具的私有能力。

### 7.2 三角色工作流

```
┌───────── 主控（主窗口会话，保全上下文）─────────┐
│ 1. 从 TASKS.md 取任务 → 写任务简报 Docs/Logs/TASK-XXX.md │
│    （目标/输入/输出/验收清单/涉及文件/约束）            │
│ 2. 派发【施工子代理】（附简报路径，要求读 AGENTS/HANDOFF）│
│ 3. 施工完成 → 派发【验收子代理】（读同一简报+施工报告）  │
│ 4. 验收 PASS → 主控 git commit + 更新 TASKS/WORKLOG/     │
│    HANDOFF → 任务关闭；FAIL → 带验收意见重派（≤3 轮，   │
│    超限挂起并标记人工介入）                              │
└──────────────────────────────────────────────┘
   施工子代理：实现+自测+跑测试+写施工报告（改了什么/怎么验的/风险）
   验收子代理：独立环境跑验收清单（编译/单测/运行检查/规范核对），出 PASS/FAIL+证据
```

- 施工与验收**必须不同子代理**（避免自证）；
- 子代理回传主窗口的只有结论摘要（长内容写入文件），主控上下文只增 KB 级；
- 主控每完成一个任务闭环，同步刷新 HANDOFF.md（见 7.4）。

### 7.3 任务与日志体系

- **TASKS.md 看板**：每行一个任务 `ID | 轨道/里程碑 | 标题 | 状态(todo/doing/blocked/done) | 简报路径 | commit`；
- **任务 ID 规则**：`A-M0-01`（Track A）/ `B-R2-03`（Track B）/ `G-01`（治理/工具通用）；
- **单任务日志 Docs/Logs/TASK-XXX.md**（模板）：
  ```markdown
  # TASK-B-R2-03 <标题>
  状态: done | 派发: 2026-10-23 | 施工: 子代理 | 验收: 子代理 | commit: <hash>
  ## 任务简报（主控写，派发原文）
  ## 施工报告（施工代理写）：实现摘要/变更文件清单/自测结果/已知风险
  ## 验收清单（主控写）
  ## 验收结论（验收代理写）：PASS/FAIL + 逐项证据（命令输出/截图路径/测试报告）
  ```
- **WORKLOG.md**：按时间倒序索引全部任务日志一行摘要（谁在何时干了什么，一眼可见）；
- 日志**必须**在派发时创建、验收通过时收口，缺任一节 = 验收不通过。

### 7.4 交接文档 HANDOFF.md（唯一权威状态源）

每次任务闭环后由主控刷新，结构固定：

```markdown
# HANDOFF —— 项目当前状态快照（<UTC 时间戳>）
## 一句话现状
## 环境（Unity 版本/路径、CMake/VS、Vulkan SDK、关键命令）
## 当前进度（里程碑表：A/B 各里程碑 done/doing/next）
## 活跃任务（doing/blocked 及其原因、下一步动作）
## 如何继续（新接管者的前三步：读什么、跑什么测试、领什么任务）
## 最近 5 条任务日志链接
## 重要注意事项（坑/未决事项/受限验证项）
```

**接管规则**（写入 AGENTS.md）：新会话/新 agent/人接手时——① 读 AGENTS.md → ② 读 HANDOFF.md → ③ 若有 doing 任务：检查工作区 `git status` 与该任务日志，判断续做或重派 → ④ 正常领 todo 任务。**禁止**凭记忆推进，一切以落盘文档为准。

### 7.5 文件规范（Docs/Standards/file-conventions.md，首任务产出）

- 编码 UTF-8 无 BOM；换行 LF（`.gitattributes` 强制，*.bat/*.ps1 例外 CRLF）；
- `.editorconfig`：C#（框架设计指南风格）、C++（LLVM 风格，4 空格）、HLSL（随 C++）；
- 命名：程序集/类 PascalCase、接口 I 前缀、私有 `_camel`、常量 `PascalCase`；C++ 类型 PascalCase、成员 `m_` 或 `s_`（在规范文档定死）；任务/日志按 §7.3 ID；
- 资产命名前缀表（`CHR_`角色/`ENV_`场景/`WPN_`武器/`UI_`/`CFG_`/`MAT_`/`TX_`…）；
- 每个源文件头部不写注释墙；公共 API 用 XML doc 注释；
- 目录即约定（v1 §7 资产管线目录不变）。

### 7.6 git 与 AGENTS.md

- **仓库即时 git init**（当前不是 git 仓库！）——主提交线 = 验收通过的任务快照，一任务一 commit：`TASK-B-R2-03: RHI D3D12 后端屏障映射`；
- `.gitignore`：Library/ Temp/ Logs/ obj/ Build/ Native/build/ 等；
- **AGENTS.md（仓库根）**：面向任何 AI agent（ZCode / workbuddy / deepseek harness 等）与人的中立指令文件：项目是什么、先读什么（HANDOFF→TASKS）、规范在哪、命令怎么跑（构建/测试/开 Unity）、什么不能动（如不 force push、不改历史 commit、不动 Library）、如何报告完成。纯 Markdown，无平台私有语法——**文档足够详细即可跨 agent 兼容**（用户已确认此策略）。
